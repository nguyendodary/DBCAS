[P027] [Heading 2] Purpose
[P029] [Normal] This document describes the Student Management System (SMS), including all main functions for users, students, and administrators.\nThe key features are listed below:
[P030] [Normal] As a student (user): can register for courses, view personal profile, and view the list of available courses.
[P031] [Normal] As an administrator (admin): can perform all CRUD (Create, Read, Update, Delete) operations on classes, users, and courses.
[P032] [Heading 2] Intended Audience and Reading Suggestions
[P035] [Heading 2] References
[P041] [Heading 1] Project Overview
[P042] [Heading 2] Project Description
[P043] [Normal] This project is developed to assist administrators in managing all courses, users and classes within Student Management System.
[P044] [Normal] It also aims to optimize the course registration process and allow students to easily view their personal profiles and the list of available courses.
[P045] [Normal] In summary, the system provides:
[P046] [List Paragraph] Efficient management of courses, classes, and users for administrators.
[P047] [List Paragraph] Simplified course registration and personal information management for students.
[P048] [Heading 2] Business Problems
[P049] [Normal] Currently, students find it difficult to register for courses, view their personal profiles, and access the list of available courses.
[P050] [Normal] At the same time, administrators face challenges in managing a large number of courses, users, and classes manually, which leads to inefficiency and errors.
[P051] [Normal] Therefore, there is a need for a centralized system that can:
[P052] [List Paragraph] Automate course registration and student management.
[P053] [List Paragraph] Reduce administrative workload.
[P054] [List Paragraph] Provide real-time access to information for both students and administrators.
[P055] [Heading 2] Business Need
[P056] [Normal] The Student Management System is needed to improve the efficiency and accuracy of managing academic information.\nCurrently, most of the operations, such as course registration, class management, and student information updates, are performed manually.\nThis manual process is time-consuming, prone to human errors, and lacks real-time data access.
[P057] [Normal] By developing this system:
[P058] [List Paragraph] Administrators can easily manage courses, users, and classes through an integrated digital platform.
[P059] [List Paragraph] Students can register for courses, view their profiles, and access course information conveniently.
[P060] [List Paragraph] The system ensures data consistency, reduces workload, and improves overall productivity for educational institutions.

[P097] [Heading 2] Software Quality Attributes
[P098] [Heading 2] Usability
[P099] [Normal] GUI
[P100] [Normal] -  All the text, image text and help documents should be in Vietnamese.
[P101] [Normal] -  The interface should be elegant, simple and out‐standing.
[P102] [Normal] -  All images must also provide alt attribute.
[P103] [Normal] Usability for end‐users
[P104] [Normal] -  Searching tool should be easy to use.
[P105] [Normal] -  The website must provide a help page to support novice users.
[P106] [Normal] -  Users can use main functionality of the system without logging in to the system.
[P107] [Normal] -  The system should remember information (but not confidential) that users have to
[P108] [Normal] provide regularly. For example: name, address…
[P109] [Normal] Usability for admin and staff
[P110] [Normal] -  Website admin and shop’s staff should need no more than one day of training to be
[P111] [Normal] productive with the system.
[P112] [Normal] -  Detailed help must be available for the admin and staff, both in web pages and separate
[P113] [Normal] documentations.
[P114] [Normal] Installation
[P115] [Normal] -  The system must be easy to deploy. Customer can deploy successfully and learn to
[P116] [Normal] configure, maintain the system within one day of training.
[P117] [Normal] -  The documentation for installation must be included. It describes detailed steps for
[P118] [Normal] installing or deploying the system. The customer can follow the steps without direct help from
[P119] [Normal] the developing team.
[P120] [Heading 2] Reliability
[P121] [Normal] -  Initial data must be collected carefully and correctly
[P122] [Normal] -  The database must be backed up regularly and can be recovered if necessary
[P123] [Normal] -  Have a good spam filter
[P124] [Normal] -  Rating system must be reliable
[P125] [Normal] -  Not conflict with other software
[P126] [Normal] -  Rate of fault occurrence (ROFO): a number of 0.005 is acceptable. It means that it is
[P127] [Normal] acceptable to have 5 failures happen in each 1000 operational time units (e.g. 5 failures per
[P128] [Normal] 1000 hours of operation).
[P129] [Normal] -  Mean Time Between Failures (MTBF): 1 month
[P130] [Normal] -  Mean Time To Repair (MTTR): immediately when admin finds out problem or website is attacked by someone. Average 1 day.
[P131] [Normal] -  Accuracy: precision of floating number should be rounded to 0.01. All currency units must be displayed (e.g. $, VND…)
[P132] [Normal] -  Maximum Bugs or Defect Rate: 5 bugs / KLOC.
[P133] [Normal] -  Bugs or Defect Rate
[P134] [Normal] o  Minor bugs: bugs related to GUI
[P135] [Normal] o  Significant bugs: bugs related to minor business logic
[P136] [Normal] o  Critical bugs: function can’t execute correctly, completely loss of data,
[P137] [Normal] disconnect to the server
[P138] [Heading 2] Security
[P139] [Normal] -  Privacy: the system should provide protection method for protecting user information from
[P140] [Normal] outside or from other users. All the information of users must not be available for anyone or
[P141] [Normal] software that is not part of the system. User password is also invisible for the system
[P142] [Normal] administrator.
[P143] [Normal] -  The system must provide methods to prevent common security attacks. E.g. SQL injection,
[P144] [Normal] Ddos,…
[P145] [Normal] -  Transformation of confidential information must be encrypted.
[P146] [Normal] -  The system must provide secure methods for users to recovery their password, including
[P147] [Normal] the interference of system’s admin.
[P148] [Normal] -  Secure information of customers should not be stored on customer’s machine.
[P149] [Normal] -  Utilize certain cryptographic techniques for database
[P150] [Normal] -  Provide options for users to choose whether to share private information
[P151] [Normal] -  Restrict communications between some areas of the program
[P152] [Normal] -  Check data integrity for critical variables
[P153] [Normal] -  Must use secure connection (SSL) for transferring sensitive data
[P154] [Heading 2] Maintainability
[P155] [Normal] Coding standards and naming conventions
[P156] [Normal] -  Output of the project must include coding standards and naming conventions
[P157] [Normal] documentations. Implementation code must be easy to maintain.
[P158] [Normal] -  All code must be clearly commented, including class, method documentations.
[P159] [Normal] -  If some components are reused, the documentations of those components must also be
[P160] [Normal] included.
[P161] [Normal] Design
[P162] [Normal] -  The design of the system must be loosely coupled that chances on some module will not
[P163] [Normal] affect others.
[P164] [Normal] Logging
[P165] [Normal] -  All the errors should be logged, supporting for bug fixing and maintenance.
[P166] [Normal] -  All strange or sensitive situations should also be logged.
[P167] [Normal] Email
[P168] [Normal] -  The system must provide an email address to receive customer feedback or send emails.
[P169] [Heading 2] Portability
[P170] [Normal] Website can be used by any people with a browser and an Internet connection..
[P171] [Heading 2] Performance
[P172] [Normal] Load time
[P173] [Normal] -  Every page should be completely displayed within: average 1.5 second and maximum 5
[P174] [Normal] seconds.
[P175] [Normal] -  Searching should return and display the result within 2 seconds.
[P176] [Normal] -  Comments and rating and the like should affect immediately, without reloading the web
[P177] [Normal] page.
[P178] [Normal] -  Frequently accessed data must be cached
[P179] [Normal] -  Reference data must be cached
[P180] [Normal] Mailing system
[P181] [Normal] -  Mail server should send emails within 1 minute after associated events happen.
[P182] [Normal] Capacity
[P183] [Normal] -  The system should serve correctly and reasonably with at least 1000 online users at a
[P184] [Normal] moment.
[P185] [Normal] -  The system can store at least 100000 places and 10000 users without affecting the loading
[P186] [Normal] speed.
[P187] [Normal] -  If the system is busy, it has to inform users about that.
[P188] [Normal] Compatibility
[P189] [Normal] -  The system should provide elegant responses for nowadays common screen resolutions:
[P190] [Normal] 1024*768, 1280*800.
[P191] [Normal] -  The output must be compatible with all common browsers: Mozilla Firefox, Internet
[P192] [Normal] Explorer, Google Chrome, Apple Safari, and Opera.
