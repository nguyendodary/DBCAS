T3R0: Table Name | Short Description
T3R1: Account | Stores login credentials for learners and administrators, including email, password hash, account status, password-set/change flags, the role-management capability flag, and creation date.
T3R2: Role | Defines the two system roles used for role-based access control: Learner and Administrator. The User role is implemented as Learner and the Admin role as Administrator.
T3R3: AccountRole | Junction table resolving the many-to-many relationship between Account and Role, recording role assignment timestamps.
T3R4: UserProfile | Holds personal details of users linked one-to-one to their Account (full name, student code, phone, date of birth); identifying fields are stripped before any external LLM call (NFR-07).
T3R5: CourseLearningOutcome | Course learning outcomes (CLOs) defined by administrators and aligned to the university database course curriculum (FR-02).
T3R6: Concept | The Core PostgreSQL concept model, organized by subject area with a base difficulty level and sql_feature, keywords and learning objectives used for practice selection and recommendations (FR-02, FR-14).
T3R7: CLOConcept | Junction table mapping course learning outcomes to PostgreSQL concepts; records whether each mapping was set by an administrator or suggested by assistive AI, and its confirmation status (FR-03).
T3R8: Question | The Administrator-approved, validated question bank: multiple-choice, SQL, and short essay items with prompt, reference answer, explanation, difficulty, points, provenance tags and source references, source (bank or AI-generated), lifecycle status, and family/version lineage (FR-04).
T3R9: QuestionConcept | Junction table tagging questions with PostgreSQL concepts, including whether a technique is mandatory and the review status of AI-recommended tags, which remain unconfirmed until reviewed by an administrator (FR-05, FR-09).
T3R10: MCQOption | Answer options for multiple-choice questions, including the verified correct-answer flag used for instant grading (FR-08).
T3R11: SQLTestDataset | Test datasets for practical SQL questions: setup SQL executed inside the Docker sandbox and expected result sets, including edge cases (FR-09).
T3R12: Rubric | Grading rubric levels (Complete, Mostly Complete, Partial, Incomplete) with score ranges and criteria for rubric-guided essay evaluation (FR-10).
T3R13: Assessment | Legacy prebuilt assessment definition retained for historical rows only: question count and duration, target type mix, historical release policy and family/version lineage. Migration 019 closes published definitions; no current API creates one.
T3R14: AssessmentConcept | Legacy junction table holding the target concepts of a retired assessment, their allowed difficulty range, and its passing benchmark; current learner-defined practice snapshots a 70% target in the session configuration.
T3R15: AssessmentSession | One learner's practice run: status, frozen configuration snapshot (including bank/AI source), optional legacy assessment id (nullable since migration 018), question locale, start and expiry times, submission time, start-request id, and review/release status, including automatic submission when the timer reaches 00:00 (FR-07).
T3R16: Attempt | One row per served question: the learner's answer (selected option, SQL text, or essay text), an immutable question snapshot, draft state, grading status, the graded score, and standardized grading evidence (FR-11).
T3R17: SelectionLog | Audit log of every question-selection decision (chosen concept, difficulty, question type and whether a fallback item was used), used to monitor selection quality (FR-15, RSK-06).
T3R18: ConceptCompetency | Per-concept competency result of a session: points earned vs. points possible on a widened two-decimal scale, the computed percentage, and the below-target flag (FR-12, FR-13).
T3R19: CompetencyGap | Concepts flagged as gaps and their LLM-generated explanations, with a context hash so identical sanitized explanations are reused. The ranked study list is derived from ConceptCompetency and the session's frozen concept targets (70% for learner-defined practice), ordered by target_pct minus competency_pct; it is not stored separately (FR-14).
T3R20: LLMCache | Cached external LLM responses keyed by a hash of the sanitized request, used to reduce API cost and latency (RSK-03).
T3R21: QuestionCandidate | AI-generated drafts held outside the Question bank; automated checks cover answer completeness, duplicates, and SQL task/reference-answer execution on test datasets. An Administrator then approves the candidate before it is stored as a validated Question and becomes servable (FR-15, NFR-09).
T3R22: AccountIdentity | Google/GitHub identity for sign-in and sign-up, with provider user id and verified-email flag. Matching verified emails link one account; new accounts receive Learner.
T3R23: AccountRoleAudit | Immutable audit trail of role grants, revocations and the one-time role-manager bootstrap, including actor, target, and previous/new role.
T3R24: OAuthHandoff | Single-use, short-lived hashed handoffs exchange a verified Google/GitHub identity for rotating access/refresh sessions without tokens in URLs.
T3R25: LoginThrottle | Server-side brute-force protection: hashed login keys with recent failure timestamps and an expiry window.
T3R26: ConceptDependency | Directed prerequisite edges between concepts (prerequisite to dependent concept); duplicate edges are blocked by the primary key and cycles are checked by the service layer.
T3R27: QuestionTranslation | Locale-specific (for example Vietnamese) prompt, explanation, option texts and rubric criteria for a question; English remains canonical on Question, MCQOption and Rubric.
T3R28: SessionQuestionPlan | Frozen ordered list of questions reserved for a practice session, including items not yet served, so later bank edits cannot alter an in-progress session; the complete plan is stored before question one (FR-15).
T3R29: SessionStartRequest | Idempotency ledger binding each learner's start or resume request id to a session, replayable after the session has completed.
T3R30: GradingJob | Durable work queue and lease for SQL and essay grading, with retry counters, availability time and failure classification.
T3R31: GradeReview | Human review decision for the mandatory administrator approval: automated evidence, reviewer, approved score and comments.
T3R32: ResultReleaseEvent | Immutable history of every session release-status transition (auto grading, pending review, reviewed, published, grading failed).
T3R33: AssessmentBlueprint | Legacy, versioned evidence mix of a retired formal definition: subject area, band, question counts, scoring weights, evidence types and approval basis. Kept for historical sessions only.
T3R34: AdaptiveEvent | Historical audit of adaptive batch or decision events, including mid-session shortage notices; retained for sessions created before learner-defined practice.
T3R35: PasswordResetToken | Single-use, short-lived password-reset tokens stored only as SHA-256 digests, with expiry, use and revocation timestamps.
T3R36: PasswordResetAudit | Immutable audit trail of password-reset requests and completions.
T3R37: AssessmentQuestion | Legacy junction table listing the curated exam question pool of a retired assessment (migration 017); unused by learner-defined practice.
T3R38: EvaluationRecord | Standardized grading evidence for one answer or scope: question snapshot, rubric result, points, evaluator source, hashes and validation flags.
T3R39: GradeEditAudit | Immutable audit of every manual grade change: attempt, reviewer, old and new score, reason and timestamp.
T3R40: RefreshSession | Hashed refresh-token families for email and OAuth sign-in, with credential version, expiry, use and revocation timestamps.
T3R41: SystemSetting | Runtime settings row retained for historical/operational values; result release is no longer selectable.
