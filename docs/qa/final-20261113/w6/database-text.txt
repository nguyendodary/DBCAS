[64] (Heading 1) Introduction
[65] (Normal) The Database Design maps the logical data model to the target database management system, considering the system’s performance requirements. It converts logical or conceptual data constructs to physical data constructs (e.g., tables, etc.) of the target Database Management System.
[66] (Heading 2) Purpose
[67] (Normal) The Database Design aims to ensure that every database transaction of the DBCAS platform — learner accounts, account recovery, the concept taxonomy, the question bank, learner-defined practice sessions, attempts, and competency results — is processed and stored reliably. It describes the PostgreSQL 17 schema that persists all application data for the AI-assisted database competency assessment and skill gap analysis system.
[68] (Heading 2) Scope
[69] (Normal) The Database Design Document has the following objectives:
[70] (List Paragraph) To describe the design of a database, that is, a collection of related data stored in the PostgreSQL DBMS, which supports the DBCAS practice workflow (CLO mapping, question banking, SQL sandbox evaluation, rubric grading, and competency gap reporting).
[71] (List Paragraph) To serve as a basis for implementing the database and related software, including the FastAPI backend, the Docker-isolated PostgreSQL sandbox, and the LLM-assisted grading pipeline.
[72] (Heading 2) Introduction about PostgreSQL
[73] (Normal) PostgreSQL is a powerful open-source relational database management system (RDBMS) known for standards compliance, reliability, and extensibility. It supports advanced data types such as JSONB, full ACID transactions, and rich indexing, which makes it well suited as the system of record for DBCAS.
[74] (Normal) PostgreSQL provides high performance and scalability through features such as MVCC, cost-based query optimization, and parallel query execution. For DBCAS, it stores the concept taxonomy, the question bank, practice session state, attempts, and per-concept competency results.
[75] (Normal) In PostgreSQL, data is organized into tables with well-defined schemas. Constraints such as primary keys, foreign keys, unique constraints, and default values enforce data integrity across the 41 tables of the DBCAS schema, while JSONB columns keep flexible evidence payloads — grading detail, selection decisions, immutable snapshots, and cached LLM responses — queryable.
